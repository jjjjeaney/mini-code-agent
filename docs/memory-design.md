# 记忆系统设计

先说清记忆分几层、每层现在到哪一步，再说**还没建的那一层**——长期记忆——打算怎么做。

`known-issues.md` 记的是"现在哪里不对、哪里是取舍"；这份记的是"还没建的东西长什么样、
为什么这么长"。落成代码之后，把这里真正的取舍搬一条进 known-issues。

---

## 一、现在有什么

| 层 | 活多久 | 管什么 | 落在哪 | 状态 |
| --- | --- | --- | --- | --- |
| 会话上下文 | 一次会话 | 这一轮说过的话 | `runagent(messages=...)` + `.agent/sessions/*.jsonl` | 做了 |
| 工作记忆 | 一次会话 | "这文件读过""这个文件别再问" | `tools/base.py` 的 `read_state`、`permissions.py` 的 `Grants` | 做了，**刻意不落盘** |
| 项目规矩 | 跟着仓库走 | "测试一律 `uv run --no-sync`"这类 | `AGENTS.md` → `system_prompt.py` | 做了 |
| 历史的体积 | 一次会话 | 旧的工具结果折成一句 | `trimming.py` | 做了 |
| 历史的内容 | 一次会话 | 旧的一段对话压成摘要 | `summarizing.py` + 会话文件里的 `summary` 行 | 做了 |
| **长期记忆** | **跨会话** | 跨会话还成立的事实 | `memory/` | **还没做**（这份文档说的就是它） |

工作记忆为什么刻意不落盘：`Grants` 是"这一次会话别再问"，重开一次就该重新问；`read_state`
是"这个 agent 读过这个文件"，重开之后模型重读一遍很便宜，而把旧的 mtime 搬回来反而会骗人
（文件早变了，记录却说"读过"）。

---

## 二、边界：长期记忆不是 AGENTS.md

`AGENTS.md` 已经进 system prompt 了。如果长期记忆也往那儿写，就会出现两个地方都能写"项目
约定"，人不知道该写哪儿。分开的标准是**跟着谁走**：

| | 谁的 | 跟着什么走 | 入库吗 |
| --- | --- | --- | --- |
| `AGENTS.md` | 人写给项目的规矩 | 仓库（换台机器也带走） | 入，跟着版本库 |
| 长期记忆 | agent 攒的事实、用户的偏好 | 这台机器这个用户 | 不入库（在 `.agent/` 里） |

一句话：**规矩写进仓库，事实留在本机。**

---

## 三、存储与召回

### 存储

- 一条记忆一个文件：`.agent/memory/<name>.md`
- 索引：`.agent/memory/MEMORY.md`
- 文件格式（frontmatter + 正文）：

```markdown
---
name: user-preference-tabs
description: 缩进用 tab，不用空格
type: user
source: user
created: 2026-10-12
---

用户偏好：缩进用 tab。改任何文件都按这个来。
```

### 召回

`MEMORY.md` 顶进 system prompt；模型看着这份清单**按需**取正文（靠一个工具，不靠 `read_file`，
理由见第六节）。索引一行就是：

```markdown
- [缩进用 tab](user-preference-tabs.md) — 缩进用 tab，不用空格
```

### 索引必须小，而且这件事有硬理由

索引是**每一次请求**都要发的 token，而且是 prompt cache 前缀的一部分——**索引改一个字，整个
缓存重建**。

这条决定了后面所有事：

- 索引里只放"名字 + 一行说这行是什么"，正文一律按需读。别想着"反正不大就塞进去"。
- `name` 和 `description` 是召回质量的全部：模型只能靠这两样判断"这条跟我现在要干的事有
  没有关系"。写清楚是投资，不是啰嗦。
- 写记忆会改索引 → 会重建一次缓存。所以"写"这件事不该频繁发生（这也是下面提取要经批准的
  一个附带理由）。

### 用的时候：用户当场说的 > 记忆里记的

记忆是**过去某一刻的快照**——可能过期了，可能是当时理解偏了，而且多半是模型自己写的。用户
现在这句话才是当下的意图。两者对不上，按用户说的来。

这条要**写给模型看**（在 system prompt 那段里明说），不然它可能拿一条旧记忆去跟用户争。

**但这不等于记忆就该被改。** 撞上冲突时的正确动作是**问一句**："这条记忆跟你刚说的对不上，
要更新它吗？"——不是默默按新的来，也不是默默把旧的改掉（改记忆仍要走第四节的批准）。这和
第五节"只提示不自动整理"是同一条道理：**记忆的变化要有人看见**。

同一个道理也适用于 `AGENTS.md`：它同样是"以前写下来的"。冲突时先按用户说的来，然后问一句
要不要改那个文件。

## 四、提取：模型提议，用户批准

三个选项：

1. **模型显式提议、用户点头**（选它）。给它一个"我想记这条"的工具，把整条内容摆出来给人看，
   点了头才写。
2. 用户手写。最可控，但要用的时候想不起来写。
3. ~~自动提取~~：从对话里自动总结"值得记的东西"。**不做**，理由见下。

自动提取为什么不做的三条：

- **它是永久注入**。记忆会进每一次请求的 system prompt，等于一句话写进去就永远在那儿了。
- **它有投毒面**。模型的输入里有别处来的内容，而那些内容不是我们能担保的（bash 输出那层
  涂黑是启发式，`known-issues` A3 自己写着"不是边界"）。"读到一个文件、里面写着'以后都这么
  干'、然后记下来"就是一条持久化投毒路径。**人点头是唯一的刹车**。
- 收益小。判断"值不值得记"要额外一次模型调用，还要处理冲突和过期——它制造的麻烦比它省的事多。

批准怎么做：复用现成的 `Prompter`（`prompts.py`），和 `ask_user`、权限确认是同一套机制——
记忆的写入是"以后每一次都生效"的事，和确认一次改文件不是一类。

---

## 五、整理：只做对账，不做自动合并

"整理"听起来像"定期把重复的合并、把过期的删掉"。**只做前一半，而且只做提示。**

### 写之前查重

新写一条时，比对已有的名字和描述，像的提示一句"已经有类似的了：`xxx`，是要覆盖还是新建"。
去重靠**写之前查**，不靠事后合——人写的时候顺手做的事，比事后再来一趟可靠。

### 会话开始时对账

每条记忆多记两样：什么时候写的（`created`），以及"它说的那件事当时是什么状态"（比如相关
文件的指纹）。会话开始时 harness 对一遍，发现对不上就提示一句"这条记忆可能过期了：……"。

**只提示，不改**。

### 为什么不让模型自动整理

- 整理是**有损**的：合并丢细节、删错就没了。
- 它同样会被投毒思路利用（"这条重复了，删掉吧"）。
- 省的是用户几分钟，赔的是"记忆可能被悄悄改坏"。

## 六、分类：按内容分三类，"谁写的"降级成字段

能用的轴有三个：**谁的事**（关于用户／关于项目／关于怎么做某件事）、**什么时候失效**、
**谁写的**。只能挑一个当主键，不然一定打架。挑**内容**：

| `type` | 装什么 | 为什么它值得单独一类 |
| --- | --- | --- |
| `user` | 关于人的：偏好、习惯、怎么跟他沟通 | 想一次看全"我对这个人知道些什么" |
| `project` | 关于这个项目的：约定、命令、边界 | 它**换仓库就该失效**，得能一眼看清哪些绑在这个项目上 |
| `reference` | 外部指针：文档地址、服务在哪、去哪儿看 | 它**自己会过期**，需要单独对账（链接可能已经死了） |

**"用户明确教的"和"模型自己推的"不分两类。** 那个区分很重要，但它是**置信度**，不是内容——
做成 frontmatter 里一个 `source: user | agent` 字段。挤进 `type` 会让"这条讲什么"和"这条可不可
信"纠缠在一起，两边都查不清。

---

## 七、落地会撞到的三件事

1. **模型写不了 `.agent/` 下的文件。** `.agent` 现在在 `SENSITIVE_DIRS` 里（会话落盘那一步
   加的），所以 `write_file` 会被闸门挡。**这正好**——记忆的写必须走 harness 自己的代码，
   它才能：校验 frontmatter、查重、更新索引、并且经用户批准。
2. **`.agent` 在容器里仍然可读**（`known-issues` A2）。记忆落在那儿，容器里的 `cat` 读得到。
   目前没破，但它是这个设计的已知边界；A2 那条修法（挂上层 + 逐个挂子目录）同样适用于它。
3. **读正文要不要走 `read_file`？** 不要——`.agent` 是敏感目录，`read_file` 读不到。要一个
   专门的工具（`read_memory(name)`），由 harness 直接读文件。顺带的好处是：那个工具可以只
   认 `<name>.md` 这种形状，天然挡掉"顺着路径跑到别处去"。

---

## 八、不做的

- **自动提取**（第四节）
- **自动整理**（第五节）
- **向量检索**：按描述找记忆，规模小的时候没必要；索引全在 system prompt 里，模型自己看得见。
- **跨机器同步**：记忆在本机不入库，这是第五节那张表定的；要共享的写进 `AGENTS.md`。

---

## 九、最小落地顺序

1. `memory/` 的读写：frontmatter 解析、索引生成、按名字取正文。
2. `remember` 工具：模型提议 → 走 `Prompter` 批准 → harness 写文件 + 更新索引。
3. `read_memory` 工具：按名字给正文。
4. 索引拼进 system prompt（`system_prompt.py` 里加一段，和 `AGENTS.md` 并列）。
5. 会话开始时的对账提示（第五节）——可以放到最后，先没有它也能用。
