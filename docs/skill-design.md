# 技能（skill）设计

`.agent/skill/<名字>/SKILL.md` 一份一个目录，索引 `SKILLS.md` 自动生成。要用的那一刻，模型
用 `read_skill` 把正文取出来照着做。

---

## 一、它和另外两样东西的分界

现在系统提示里能进来的"外部输入"有三样，分界按**内容**走：

| | 是什么 | 拿来干嘛 | 谁写的 | 放哪 |
| --- | --- | --- | --- | --- |
| `AGENTS.md` | 项目的**规矩** | 一直遵守 | 人 | 仓库（跟着版本库走） |
| 长期记忆 | **事实** | 判断（"这个项目测试用 uv"） | 人和 agent | `.agent/memory/` |
| **技能** | **步骤** | 照做（"发版前按这份清单走一遍"） | 人 | `.agent/skill/` |

一句话：**规矩常驻、事实用来判断、步骤用来执行。**

`docs/memory-design.md` 第二节那条"规矩写进仓库，事实留在本机"是照着前两样定的。技能是第三
样，它两者都沾一点——**是人写的（像规矩），但留在本机（像事实）**。这么定是因为技能通常和
这台机器上的环境绑着（哪个路径、哪个命令、装了什么）。哪天想让一个团队共用一份技能，得换个
地方放（入仓库），那是个要单独想的事。

---

## 二、形状

```
.agent/skill/
  release/
    SKILL.md          ← frontmatter(description) + 正文（要照着做的步骤）
    check.sh          ← 附件：脚本、模板、参考文档，随便放
    templates/note.md
  SKILLS.md           ← 自动生成的索引（跟 MEMORY.md 一样）
```

`SKILL.md` 只有一样必填：

```
---
description: 发版前按这个走一遍
---

1. 跑 uv run --no-sync pytest
2. ...
```

**不放 `name`**：名字就是目录名。两处都写迟早会不一致，而目录名躲不掉。

**索引自动生成**（`sync_index`，跟记忆同一套）：手写必漂，而且这条已经为记忆踩过一次。
提示词里那份是**现算**的（每次扫目录），磁盘上那个 `SKILLS.md` 只是给人翻的副本——所以手工
加一份、还没重建索引，下次拼提示词就已经能看见它了。

---

## 三、怎么进模型

**两段式**（和记忆一样，也是唯一可行的做法）：

1. **清单常驻**：每份只有名字和一句 `description`，进 system prompt。它排 `AGENTS.md` 后面、
   记忆清单前面——按"变得多勤"排的：技能只在人加删时变，记忆会随 `remember` 长。
2. **正文按需取**：`read_skill(name)` 取正文，末尾附上这个目录里有哪些附件；附件用
   `read_skill_file(name, path)` 取。

**`description` 要写成"什么时候用得上"，不是"这是什么"。** 光把清单摆出来模型不会主动去取
（记忆那边实测过）；技能还多一层——**它不会觉得自己需要一个自己不知道存在的东西**。所以提示
词里那句"动手之前先扫一遍"是必须的，不是客套。

---

## 四、安全

三处，缺一不可：

**一、只有人写。** 没有 `remember` 那样的写入工具。记忆至少是"事实"，技能是"步骤"——不该让
模型自己给自己立规矩。

**二、`.agent/` 在容器里挂只读。** 项目目录整个是可写挂进去的，`.agent` 单独盖一层只读
（和 `.git` 同一个写法）。理由和 `.git` 那条一字不差，而且更硬：**里面装的全都是"会在宿主机上
生效"的东西**——会话流水、改前备份、记忆、技能。技能尤其要紧：一条 `bash` 命令往
`.agent/skill/` 里写一个，下一轮（索引每轮重扫）模型就会照着它做。

**三、加载器是单独开的一道门。** 技能在 `.agent/` 底下，文件工具够不着（那是敏感目录，刻意的
——里面还有会话流水和改前备份）。所以 `read_skill` / `read_skill_file` 是 harness 自己开的
门，`read_skill_file` 的围栏是**"这个技能自己的目录"**：名字先过校验（挡 `../`），路径再过
`resolve_inside`，路径上有符号链接也拒。这是本项目第三条读文件的路径，闸门一道都不能省。

---

## 五、知道了但先不做的

- **技能入库**（跟着仓库走、团队共用）——那样它就和 `AGENTS.md` 争位置了，得先说清规矩和步骤
  的边界。见第一节末尾。
- **让模型自己攒技能**——想过，第一版按"只有人写"定。理由见第四节第一条。
- **技能里带可执行的钩子**（比如 `SKILL.md` 里声明"用之前先跑 check.sh"）——现在的模型得自己
  决定跑不跑，而它跑什么都要过权限那一关。这层自动执行是另一摊事。
